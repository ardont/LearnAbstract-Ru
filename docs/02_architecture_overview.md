## 1. Архитектурный стиль: Событийно-ориентированные микросервисы (EDA)

Архитектура «Твой Путь» спроектирована по принципам **Event-Driven Architecture (EDA)** с разделением на независимые сервисы и асинхронную шину событий **Apache Kafka (режим KRaft)**.

```
       [ Ученик в MAX ]                [ Веб-портал Ученика ]           [ Кабинет Учителя ]
      (@t569_hakaton_max_bot)          (http://.../student)             (http://.../teacher)
                 │                                │                                │
                 ▼                                └────────────────┬───────────────┘
       ┌──────────────────┐                                        │
       │   BOT SERVICE    │ ─── HTTP / REST (Internal) ───────────┤
       │   (порт 8001)    │                                        │
       └─────────┬────────┘                                        ▼
                 │                                  ┌─────────────────────────────┐
                 │                                  │        CORE SERVICE         │
                 │                                  │         (порт 8000)         │
                 │                                  │  • BFF, FSM, Rate Limiter   │
                 │                                  │  • Аутентификация учителя   │
                 │                                  │  • RAG Ingest учебников     │
                 │                                  └──────┬───────────────┬──────┘
                 │                                         │               │
                 ▼                                         │               ▼
      ┌────────────────────────────────────────┐           │       ┌───────────────┐
      │          APACHE KAFKA (KRaft)          │           │       │   ХРАНИЛИЩА   │
      │  Топики:                               │           │       │ • PostgreSQL  │
      │  • education.events                    │◄──────────┘       │ • Redis       │
      │  • education.events.dlq (Dead Letter)  │                   └───────────────┘
      └──────────────────┬─────────────────────┘
                         │
                         ▼
      ┌────────────────────────────────────────────────────────────┐
      │                         ML SERVICE                         │
      │                        (порт 8002)                         │
      │  • BM25 Okapi RAG Engine (поиск по учебникам)              │
      │  • LLM Client (DeepSeek / Ollama) + Prompt Orchestration   │
      │  • 3-Tier Fallback Catalog (100 проверенных метафор)       │
      │  • Guardrails (безопасность + конвертер LaTeX -> Unicode)  │
```

## 2. Разделение ответственности сервисов (Separation of Concerns)

| Микросервис | Технологический стек | Основная ответственность |
| :--- | :--- | :--- |
| **Core Service** (порт 8000) | Python 3.11, FastAPI, SQLAlchemy 2.0 (async), PostgreSQL / SQLite, Redis | **BFF (Backend-for-Frontend)**, конечный автомат учеников (FSM), соблюдение 152-ФЗ, Rate Limiter, сессии квизов, дашборд учителя, мониторинг `/health/full`. |
| **ML Service** (порт 8002) | Python 3.11, FastAPI, BM25 Okapi, Snowball / pymorphy3, DeepSeek / Ollama | **Интеллектуальный конвейер**: формулобезопасный чанкинг, извлечение чанков учебников через RAG, синтез метафор, Output Guardrails, Fallback-каталог (100 метафор). |
| **Bot Service** (порт 8001) | Python 3.11, umaxbot / aiomax, aiokafka, Redis | **Шлюз мессенджера MAX**: дедупликация вебхуков (`idempotency.py`), классификатор намерений, Watchdog-таймеры (45 сек), инлайн-клавиатуры. |

> 🗺️ **Полная декомпозиция кода**: Подробный построчный разбор всех модулей, классов и каждой функции представлен в [Справочнике кодовой базы](./codebase_reference.md).

## 3. Сквозной жизненный цикл запроса («Life of a Request»)

Проследим путь запроса семиклассника Васи от нажатия кнопки в мессенджере до появления оценки в дашборде учителя:

```
[Вася в чате MAX] 
       │ 1. Пишет: "Объясни квадратные уравнения"
       ▼
┌──────────────┐
│  Bot Service │ ──► Идемпотентность: SET ingress_msg:{id} 1 EX 3600 NX в Redis
└──────┬───────┘ ──► Watchdog: заводит active_watchdog:{corr_id} на 45 сек в Redis
       │ 2. Публикует событие: "bot.command.received"
       ▼ (Топик: education.events)
┌──────────────┐
│ Core Service │ ──► Rate Limiter: проверяет скользящее окно 10 RPM в Redis ZSET
└──────┬───────┘ ──► Достает профиль Васи: интерес = "Футбол", класс = 7
       │ 3. Публикует событие: "explanation.requested"
       ▼ (Топик: education.events)
┌──────────────┐
│  ML Service  │ ──► RAG: находит 3 чанка в учебнике алгебры (BM25 Okapi)
└──────┬───────┘ ──► LLM: генерирует футбольную метафору (парабола удара, дискриминант)
       │         ──► Guardrails: очищает LaTeX в читаемый Unicode (x², √D)
       │ 4. Публикует событие: "explanation.ready"
       ▼ (Топик: education.events)
  ┌────┴───────────────────────────┐
  ▼                                ▼
┌──────────────┐            ┌──────────────┐
│  Bot Service │            │ Core Service │ ──► Записывает в PostgreSQL:
└──────┬───────┘            └──────────────┘     лог задержки и темы для Учителя
       │ 5. Снимает Watchdog в Redis
       │ 6. Отправляет Васе объяснение и инлайн-кнопки теста
       ▼
[ Вася читает метафору и нажимает правильный ответ в тесте ]
       │
       ▼
┌──────────────┐ ─── POST /api/quiz/answer ────► ┌──────────────┐
│  Bot Service │                                 │ Core Service │ ──► Quiz Freshness Guard проверяет quiz_id
└──────────────┘ ◄── Результат: "Верно! +50 XP" ─ └──────┬───────┘ ──► Начисляет баллы в БД
                                                         │
                                                         ▼
                                            [ Кабинет Учителя /teacher ]
                                            В реальном времени обновляется:
                                            • График активности класса
                                            • Тепловая карта понимания темы
```

## 4. Сквозная трассировка: `correlation_id` и `causation_id`

Все события упаковываются в единый контракт `EventEnvelope` (`shared/schemas/events.py`):
```json
{
  "event_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "event_type": "explanation.requested",
  "version": "1.0",
  "timestamp": "2026-10-07T14:30:00Z",
  "correlation_id": "c71a39f0-2f91-4d32-9c12-3498b5a034f1",
  "causation_id": "4a8e3f01-7d12-4299-8812-70b86a87e362",
  "producer": "core_service",
  "payload": { ... }
}
```

* **`correlation_id`** — сквозной идентификатор цепочки. Генерируется на входе в систему и передается без изменений через Bot Service → Core Service → Kafka → ML Service → обратно в Bot. Позволяет мгновенно отфильтровать логи в Grafana/Kibana и проследить всю историю одного запроса.
* **`causation_id`** — идентификатор непосредственного события-причины, породившего текущее событие. Позволяет восстановить причинно-следственное дерево (Event Tree).

## 5. Пакет отказоустойчивости «План Б» (Graceful Degradation)

Система защищена от сбоев внешних API и инфраструктурных падений:
1. **Сбой PostgreSQL** → автоматический прозрачный fallback на локальный **SQLite (`core.db`)**.
2. **Сбой Redis** → переход на потокобезопасные **in-memory структуры (`collections.deque` + `asyncio.Lock`)**.
3. **Сбой Apache Kafka** → сервисы переходят на **прямое синхронное HTTP REST-взаимодействие**.
4. **Сбой LLM API (таймаут / исчерпание лимита)** → мгновенный переход на **каталог из 100 выверенных метафор** за 180 мс.
